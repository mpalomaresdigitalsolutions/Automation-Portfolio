How the Workflow Works

Stage 1 · Two Entry Points

The workflow has two ways to start:

  • Telegram Trigger — a user messages your Telegram bot.
  • Webhook — an app or frontend sends a POST request.
  • Both feed into a Normalize Input node that extracts two things regardless of source: session_id (who is talking) and user_message (what they said).

Stage 2 · Strategy Agent (Multi-turn Conversation)

The normalized message goes to an AI Agent backed by DeepSeek. Its job is to act as a research planner — built on expertise across paid ads, AI automation, and client services with over 2 years of hands-on experience. The agent runs the conversation like this:

  • Greets the user and asks what they want to research.
  • Asks up to 3 clarifying questions — one at a time — to narrow the scope.
  • Presents a draft research plan and asks for confirmation.
  • Always responds with a JSON object: { "is_pass_next": true/false, "message": "..." } so downstream nodes can read the intent programmatically.
  • Memory node remembers the conversation history per session_id, so multi-turn back-and-forth works correctly across separate requests.

Stage 3 · Switch: Feedback or Proceed?

A Switch node reads is_pass_next from the agent's JSON response:

  • False (still clarifying) — sends the agent's question back to the user via webhook response and/or Telegram message. The workflow ends here and waits for the next message.

Airbnb RAG Chat Agent — FiFi

A guest-facing AI assistant for short-term rentals. Two n8n pipelines keep property knowledge fresh and answer guests semantically — property-first, DeepSeek-powered, and fully logged.

1 · Knowledge Base Updater

Keeps property information up to date automatically.

  • Property File Updated (Google Drive) — polls every hour for changes to the property info document.
  • Get File Content — downloads the updated file from Google Drive.
  • Extract from File — pulls the plain text content out of the document.
  • Supabase Vector Store Insert — chunks text (500-char chunks, 50-char overlap) and stores NVIDIA Nemotron embeddings for semantic search.

2 · RAG AI Chat Agent

The guest-facing chatbot, powered by DeepSeek.

  • When chat message received — the public "FiFi" interface greets guests and accepts their messages.
  • Captures session id — tracks conversation context within the session.
  • RAG AI Agent — DeepSeek core with simple memory, a vector-store tool (always checked first), and Wikipedia fallback for general knowledge.
  • Log Chat to Google Sheets — session ID, guest message, AI reply, and timestamp logged after every response.

Key behaviors

  • Property-first: the agent always checks the Supabase vector store before anything else.
  • Smart term matching: variations like "check in", "checkin", and "check-in" are treated identically.
  • Amenity links: responses for the hot tub, TV remote, or oven include direct instruction links.
  • Safety guardrails: declines inappropriate requests (extra guests, security info, personal host details) and directs emergencies to 911 or the host.
  • Full audit trail: every conversation is logged to Google Sheets for review.

Real Estate Market Trend Report — AI Market Intelligence

A vertical AI assistant for real estate professionals. Two n8n pipelines keep market data fresh in Weaviate and answer trend questions with grounded, cited context — DeepSeek-powered and fully logged to Google Sheets.

1 · Data Ingestion

Loads raw real estate content into Weaviate for AI retrieval.

  • Ingest Form — paste raw market reports, property listings, or trend data into a web form.
  • Default Data Loader + Splitter — splits text into 400-character chunks with a 40-character overlap for embedding.
  • Embeddings (Cohere) — converts each chunk into a vector with Cohere's embed-english-v3.0 model.
  • Insert (Weaviate) — stores vectors in the Test_jina collection for semantic retrieval.

2 · Chat Q&A + Logging

Answers real estate questions and logs every exchange.

  • When chat message received — a chat trigger receives the user's question.
  • Agent (DeepSeek) — processes the question with three sub-components: Memory (per-session history via the chat sessionId), Weaviate Tool (searches the vector database for prices, market conditions, and regional trends), and a DeepSeek Tool Model that drives the search tool.
  • Sheet (Google Sheets) — logs the query, response, and timestamp after every answer.

Key behaviors

  • Semantic retrieval: the agent grounds answers in the ingested market data before responding.
  • Conversation memory: follow-up questions retain session context.
  • Grounded, not guessed: when the vector store lacks relevant data, the agent says so and asks for more context instead of fabricating figures.
  • Full audit trail: every query and response is logged to the spreadsheet for transparency and reporting.
